# 소멸자에서의 마무리 작업

## 설명

Rust에는 함수가 어떤 방식으로 끝나더라도 실행되는 `finally` 블록과 같은 기능이 없습니다. 대신 객체의 소멸자를 사용해 함수가 종료되기 전에 수행해야 하는 코드를 실행할 수 있습니다. Rust에서 소멸자는 `Drop` 트레이트를 구현해 정의합니다.

## 예제

아래 예제의 `_exit` 값은 `bar` 함수가 어떤 경로로 종료되든 스코프를 벗어날 때 소멸자가 실행됩니다. `baz()?`에서 오류가 반환되어 함수가 조기에 끝나는 경우와 `Ok(())`로 정상 종료하는 경우 모두 `Foo::drop`이 호출됩니다.

```rust,ignore
fn baz() -> Result<(), ()> {
    // some code
}

fn bar() -> Result<(), ()> {
    // These don't need to be defined inside the function.
    struct Foo;

    // Implement a destructor for Foo.
    impl Drop for Foo {
        fn drop(&mut self) {
            println!("exit");
        }
    }

    // The destructor of _exit will run however the function `bar` is exited.
    let _exit = Foo;
    // Implicit return with `?` operator.
    baz()?;
    // Normal return.
    Ok(())
}
```

## 동기

함수에 반환 지점이 여러 개 있으면 종료 시 실행할 코드를 각 위치에 반복해서 넣어야 하므로 작성과 유지보수가 번거롭고 오류가 생기기 쉽습니다. 매크로 때문에 반환이 코드에 명시적으로 드러나지 않는 경우에는 특히 그렇습니다.

대표적인 경우가 `?` 연산자입니다. 결과가 `Err`이면 현재 함수에서 바로 반환하고, `Ok`이면 계속 실행합니다. `?`는 예외 처리와 비슷한 흐름을 만들지만, Java의 `finally`처럼 정상 처리와 오류 처리 양쪽에서 공통 코드를 실행하도록 예약하는 문법은 Rust에 없습니다. 패닉도 함수의 실행을 조기에 끝낼 수 있습니다.

## 장점

소멸자는 거의 모든 종료 경로에서 실행됩니다. 따라서 함수의 정상 종료뿐 아니라 조기 반환이나 패닉으로 스택을 푸는 상황에서도 정리 코드를 수행할 수 있습니다.

## 단점

소멸자가 반드시 실행된다고 보장할 수는 없습니다. 함수가 무한 루프에 빠지거나 종료 전에 프로그램이 충돌하면 소멸자가 실행되지 않을 수 있습니다. 이미 패닉을 처리 중인 스레드에서 또 패닉이 발생하는 경우에도 소멸자는 실행되지 않습니다. 따라서 마무리 작업이 반드시 성공해야 하는 종료 처리기로 소멸자에만 의존해서는 안 됩니다.

이 패턴은 눈에 잘 띄지 않는 암묵적 동작을 추가합니다. 함수의 본문만 읽어서는 종료 시 어떤 소멸자가 실행되는지 명확하지 않을 수 있어 디버깅이 어려워집니다. 종료 처리만을 위해 별도의 타입과 `Drop` 구현을 만드는 것도 보일러플레이트를 늘립니다.

## 논의

종료 처리에 사용할 값은 함수가 끝날 때까지 살아 있다가 함수 스코프를 벗어나면서 파괴되어야 합니다. 값 자체나 `Box<Foo>`처럼 고유하게 소유하는 포인터를 사용해야 합니다. `Rc` 같은 공유 포인터를 사용하면 함수가 끝난 뒤에도 다른 소유자가 종료 처리 값을 계속 유지할 수 있습니다. 같은 이유로 종료 처리 값을 함수 밖으로 옮기거나 반환해서는 안 됩니다.

종료 처리 객체는 변수에 대입해야 합니다. 변수에 저장하지 않으면 값이 생성 직후 파괴되어 원하는 시점에 정리 작업을 수행하지 못합니다. 종료 처리 용도로만 사용하는 변수라면 사용되지 않는 변수 경고를 피하도록 이름을 `_`로 시작하게 지정합니다. 다만 변수 이름을 접미사 없는 `_`로만 쓰면 값이 즉시 버려지므로 그렇게 해서는 안 됩니다.

Rust는 객체가 스코프를 벗어날 때 소멸자를 실행합니다. 블록의 끝에 도달하거나, 조기 반환을 하거나, 패닉이 발생해도 스택을 푸는 동안 각 스택 프레임의 객체 소멸자가 호출됩니다. 따라서 호출된 함수 안에서 패닉이 발생해도 스택이 정상적으로 풀리는 한 바깥 함수의 소멸자도 실행됩니다.

이미 패닉으로 스택을 푸는 중에 소멸자가 다시 패닉을 일으키면 Rust는 추가 소멸자를 실행하지 않고 스레드를 즉시 중단합니다. 그러므로 소멸자의 실행도 절대적으로 보장되지는 않습니다. 또한 소멸자에서 패닉이 발생하면 자원이 예상하지 못한 상태로 남을 수 있으므로 `Drop` 구현에서 패닉이 발생하지 않도록 특별히 주의해야 합니다.
