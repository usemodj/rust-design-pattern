# 컬렉션은 스마트 포인터

## 설명

[`Deref`](https://doc.rust-lang.org/std/ops/trait.Deref.html) 트레이트를 사용하면 컬렉션을 스마트 포인터처럼 다룰 수 있습니다. 즉, 데이터를 소유하는 컬렉션이 그 데이터의 빌린 뷰도 제공하도록 표현할 수 있습니다.

## 예제

`Vec<T>`는 `T` 값들을 소유하는 컬렉션이고, 슬라이스 `&[T]`는 `T` 값들을 빌려 보는 컬렉션입니다. `Vec<T>`에 `Deref<Target = [T]>`를 구현하면 `&Vec<T>`를 `&[T]`로 암시적으로 역참조할 수 있으며, 자동 역참조를 통한 메서드 탐색에서도 이 관계를 사용할 수 있습니다. `Vec`에 필요해 보이는 메서드 중 상당수는 실제로 `Vec`가 아니라 슬라이스에 구현되어 있습니다.

아래는 `Vec<T>`가 내부 저장소를 슬라이스로 노출하는 방식의 개략적인 예입니다.

```rust,ignore
use std::ops::Deref;

struct Vec<T> {
    data: RawVec<T>,
    //..
}

impl<T> Deref for Vec<T> {
    type Target = [T];

    fn deref(&self) -> &[T] {
        //..
    }
}
```

`String`과 `&str`도 비슷한 관계입니다. `String`은 문자열 데이터를 소유하고, `&str`은 그 데이터를 빌려 보는 뷰입니다.

## 동기

소유권과 대여는 Rust 언어의 핵심 개념입니다. 자료 구조를 구현할 때도 이러한 의미를 제대로 반영해야 사용하기 좋은 API를 만들 수 있습니다. 데이터를 소유하는 자료 구조라면 그 데이터를 빌려 볼 수 있는 뷰도 제공하는 것이 API를 더 유연하게 만듭니다.

컬렉션이 데이터를 소유한다는 것은 각 데이터에 접근하는 방법이 컬렉션을 통하는 것이고, 그 데이터를 삭제할 책임도 컬렉션에 있다는 뜻입니다. 일부 공유 소유권을 사용하는 경우에도 데이터에 대한 빌린 뷰를 제공하는 것이 적절할 수 있습니다. 데이터를 소유하는 컬렉션을 여러 곳에서 참조할 수 있도록 빌린 형태를 제공하는 것이 대체로 유용합니다.

## 장점

- 대부분의 메서드를 빌린 뷰에만 구현해도 소유 컬렉션에서 자동 역참조를 통해 사용할 수 있습니다. 같은 동작을 소유 타입에 반복해서 구현할 필요가 줄어듭니다.
- API를 사용하는 쪽에서 데이터를 빌릴지, 소유권을 가져갈지 선택할 수 있습니다.

## 단점

역참조를 통해서만 사용할 수 있는 메서드와 트레이트는 제네릭 바운드를 검사할 때 고려되지 않습니다. 따라서 이 패턴을 사용하는 자료 구조를 제네릭 코드에서 다룰 때 복잡해질 수 있습니다. 이런 경우 [`Borrow`](https://doc.rust-lang.org/std/borrow/trait.Borrow.html)와 [`AsRef`](https://doc.rust-lang.org/std/convert/trait.AsRef.html) 트레이트 등도 함께 살펴보세요.

## 논의

스마트 포인터와 컬렉션은 서로 비슷합니다. 스마트 포인터는 하나의 객체를 가리키고 컬렉션은 여러 객체를 가리킨다는 차이가 있지만, 타입 시스템 관점에서는 큰 차이가 없습니다.

컬렉션을 통하지 않고는 각 데이터에 접근할 수 없고, 데이터 삭제 책임도 컬렉션에 있다면 그 컬렉션이 데이터를 소유한다고 볼 수 있습니다. 컬렉션이 데이터를 소유하는 경우 데이터를 빌린 뷰로 제공하면 같은 데이터를 여러 곳에서 참조하기 편리합니다.

대부분의 스마트 포인터(예: `Foo<T>`)는 `Deref<Target = T>`를 구현합니다. 하지만 컬렉션은 보통 사용자 정의 타입을 대상으로 역참조합니다. `[T]`와 `str`은 언어 차원의 지원을 받지만, 일반적인 경우에 그런 특별 지원이 꼭 필요한 것은 아닙니다. 예를 들어 `Foo<T>`는 동적 크기 타입인 `Bar<T>`를 대상으로 `Deref<Target = Bar<T>>`를 구현할 수 있으며, `&Bar<T>`를 `Foo<T>`가 가진 데이터의 빌린 뷰로 사용할 수 있습니다.

정렬된 컬렉션은 범위(`Range`)를 이용한 슬라이싱 문법을 제공하기 위해 `Index`를 구현하는 경우가 흔합니다. 이때 인덱싱의 대상은 소유 컬렉션이 아니라 빌린 뷰가 됩니다.
