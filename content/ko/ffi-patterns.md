# FFI 디자인 패턴

## 개요

FFI(Foreign Function Interface, 외부 함수 인터페이스)는 Rust 코드가 C와 같은 다른 언어의 함수나 라이브러리와 상호작용할 수 있게 합니다. 서로 다른 언어 사이에서 함수 호출 규약(ABI), 타입의 메모리 표현, 문자열 형식, 오류 전달 방식, 메모리 소유권을 합의해야 하므로 FFI를 올바르게 설계하는 일은 그 자체로 하나의 주제입니다.

Rust와 외부 언어 사이의 경계에서는 컴파일러가 외부 포인터의 유효성이나 상대 언어의 메모리 규칙을 모두 확인할 수 없습니다. 따라서 포인터의 유효 기간, 할당과 해제 책임, 버퍼의 크기, 널 포인터 처리, 스레드 안전성 같은 조건을 API 계약으로 명확히 해야 합니다. `unsafe` 블록은 그 계약이 지켜진다고 코드 작성자가 보증하는 부분이지, 잘못된 포인터나 타입 선언을 자동으로 안전하게 만드는 기능은 아닙니다.

Rust Design Patterns 원문은 FFI 전체를 다루는 강좌를 대신하려는 것이 아니라, `unsafe` Rust를 처음 사용하는 사람이 흔히 만나는 함정을 피하도록 몇 가지 유용한 관용구를 안내합니다. 이 장의 두 중심 패턴은 메모리 안전성과 명확한 안전 경계를 만들기 위한 [객체 기반 API](/docs/ffi-object-apis)와 여러 Rust 타입을 하나의 외부 객체로 묶는 [래퍼로 타입 통합하기](/docs/ffi-wrapper-types)입니다.

## 핵심 패턴

### 객체 기반 API: 내부 상태와 수명을 핸들 뒤에 두기

Rust 쪽 객체가 상태를 소유하게 하고, 외부 언어에는 내부 표현을 알 수 없는 불투명 핸들을 제공할 수 있습니다. 외부 호출자는 공개 생성 함수로 핸들을 얻고, 해당 핸들을 받는 API로 작업한 뒤, 정해진 해제 함수로 수명을 끝냅니다.

이 방식은 외부 코드가 Rust 구조체의 필드나 내부 포인터를 직접 조작하지 않게 하며, Rust 라이브러리가 내부 상태를 한곳에서 관리하도록 합니다. 반면 외부에서 독립된 여러 반복자를 동시에 유지하거나 임의로 결합하는 동작을 제공하기 어려울 수 있습니다. 외부 사용 패턴과 안전하게 보장할 수 있는 수명을 고려해 API를 설계하세요.

자세한 내용과 예제는 [FFI를 위한 객체 기반 API](/docs/ffi-object-apis)를 참고하세요.

### 래퍼로 타입 통합하기: 연관된 상태를 하나로 묶기

Rust에서는 빌림과 수명 매개변수로 연관된 값들의 유효 기간을 표현할 수 있지만, C 인터페이스로 단순 포인터만 내보내면 그 관계가 타입에 드러나지 않습니다. 예를 들어 컬렉션과 그 컬렉션을 참조하는 반복자를 각각 외부에 노출하면, 호출자가 컬렉션을 먼저 해제한 뒤 반복자를 사용하지 않도록 별도로 책임져야 합니다.

대신 외부 핸들 하나가 컬렉션과 순회 상태를 함께 소유하도록 래핑할 수 있습니다. 외부 API는 래퍼에 `first_key`나 `next_key` 같은 작업을 요청하며, 내부 객체의 수명과 순서 제약은 Rust 구현이 관리합니다. 이때 순회 상태를 저장할지 호출할 때 계산할지에 따라 동작과 비용이 달라지므로, 래퍼 안의 상태 변경도 명확하게 정의해야 합니다.

자세한 내용과 예제는 [래퍼로 타입 통합하기](/docs/ffi-wrapper-types)를 참고하세요.

## FFI 경계를 설계할 때 확인할 사항

1. **ABI와 타입 선언을 맞춥니다.** Rust의 외부 함수 선언은 컴파일러가 실제 C 헤더와 대조해 주지 않습니다. 호출 규약, 인자 타입, 반환 타입이 외부 라이브러리의 선언과 일치해야 합니다. C에 노출하는 구조체는 필요한 경우 `#[repr(C)]`로 표현을 지정하고, Rust 전용 타입의 내부 배치를 그대로 노출하지 마세요.
2. **포인터 계약을 문서화합니다.** 포인터가 널일 수 있는지, 읽기·쓰기 중 어느 접근을 허용하는지, 몇 바이트가 유효한지, 언제까지 살아 있어야 하는지, 누가 해제하는지 정합니다. 이 조건들은 호출자가 지켜야 하는 API 계약입니다.
3. **소유권과 해제 규칙을 대칭으로 둡니다.** Rust에서 할당한 메모리를 외부 런타임의 임의 해제 함수로 해제하거나, 외부에서 할당한 메모리를 Rust의 `Box::from_raw` 등으로 임의 처리하지 마세요. 생성과 해제는 서로 호환되는 API 쌍으로 설계합니다.
4. **문자열과 오류를 경계에 맞게 변환합니다.** Rust의 `String`과 `&str`은 C의 널 종료 문자열과 표현이 다릅니다. `CString`·`CStr`을 사용하고 수명을 보장하며, Rust의 오류 타입은 외부에서 처리할 수 있는 반환 코드나 C 호환 구조체 등으로 명시적으로 변환합니다.
5. **`unsafe`와 검증 책임을 좁힙니다.** 원시 포인터를 검사하고 Rust 참조나 슬라이스로 바꾸는 부분을 최소화합니다. 안전한 래퍼를 제공할 수 있다면 외부 호출자에게 전달되는 `unsafe` 요구 사항을 줄이고, 각 `unsafe` 블록의 전제 조건을 문서화합니다.
6. **재진입과 스레드 안전성을 확인합니다.** 외부 함수가 같은 객체를 여러 스레드에서 동시에 호출하거나 콜백을 통해 Rust로 다시 들어올 수 있는지 검토합니다. 내부 상태가 이를 지원하지 않는다면 동시 호출을 금지하거나 동기화 정책을 API에 명시해야 합니다.

이 목록은 모든 FFI 계약을 대신하지 않습니다. 외부 라이브러리의 문서와 헤더를 확인하고, 대상 플랫폼과 ABI에 맞는 통합 테스트를 수행해야 합니다.
