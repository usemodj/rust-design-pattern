# 소개

소프트웨어를 만들다 보면 서로 다른 환경에서도 되풀이되는 문제가 나타납니다. 구현 세부 사항은 다르더라도, 여러 상황에 적용할 수 있는 공통 해법을 찾아 추상화할 수 있습니다.

디자인 패턴은 반복되는 문제에 재사용할 수 있도록 정리하고 검증한 해결 방식입니다. 코드를 모듈화하고 유지보수하기 쉽게 만들며, 팀 안에서 설계 의도를 공유하는 공통 어휘가 되어 줍니다.

다만 패턴마다 장단점이 있습니다. 패턴을 적용하는 것 자체보다 **왜 이 패턴을 선택했는지**가 더 중요합니다. 필요하지 않은 추상화는 오히려 코드를 복잡하게 만들 수 있습니다.

## Rust에서 패턴을 바라보는 법

Rust는 객체 지향 언어의 관습을 그대로 따르지 않습니다. 함수형 프로그래밍 요소, 강한 타입 시스템, 소유권과 빌림 검사기가 함께 작동하므로 다른 언어의 패턴을 그대로 옮기기보다 Rust의 특성에 맞게 표현해야 합니다.

이 안내서는 원문의 주제를 관용구, 디자인 패턴, 안티 패턴으로 나누어 소개합니다.

- **관용구**는 Rust 커뮤니티에서 널리 받아들여진 코딩 방식입니다.
- **디자인 패턴**은 반복되는 설계 문제를 해결하는 접근 방식입니다.
- **안티 패턴**은 문제를 해결하는 듯 보이지만 장기적으로 복잡성이나 오류 가능성을 키우는 방식입니다.

## 읽는 방법

예제를 그대로 복사하기보다는, 코드가 어떤 소유권 경계를 표현하는지와 선택한 추상화가 실제 요구에 맞는지 살펴보세요. 하나의 패턴이 모든 상황에 맞는 것은 아닙니다.
